0. 引言

假设我们要维护一组待处理的任务。每个任务都有一个优先级，新的任务随时可能加入；每次处理任务时，需要取出当前优先级最高的那个。

如果把任务放进一个无序数组，每次取出最高优先级的任务，都要扫描整个数组。如果始终保持数组有序，取出端点元素很方便，但插入新任务时可能需要移动大量元素。

我们希望把优先级最高的元素放在容易访问的位置，同时让每次插入、删除只影响少量元素。接下来先明确这些操作需要满足的要求，再用一棵二叉树组织数据，逐步得到堆的结构。

1. 优先级队列

普通队列按进入的先后顺序取出元素。优先级队列按优先级取出元素，每次返回当前优先权最高的元素。

“优先级最高”需要由具体问题定义。例如，任务的数值越小越紧急，就应每次取出最小值；数值越大越重要，就应每次取出最大值。

以数值越小越优先为约定，最小优先级队列至少需要两种操作：

操作 输入 结果
Insert(x) 待加入的元素 x 将 x 加入集合
Remove(x) 用于接收结果的变量 x 删除当前最小元素，将其写入 x

还可以提供 Top()，只读取最小元素，保留集合不变。空队列没有最小元素，因此删除和读取堆顶都需要规定空队列时的处理方式。

优先级队列描述了我们希望获得的行为。堆是一种实现这些行为的数据结构。对于整数，可以直接比较数值；如果元素是一条任务记录，就比较记录中的关键码，也就是决定优先级的字段。

最小优先级队列的接口可以写为：

template <class T, class E>
class MinPQ {
public:
    virtual bool Insert(const E& x) = 0;
    virtual bool Remove(E& x) = 0;
    virtual ~MinPQ() = default;
};

E 表示元素类型，T 预留为关键码类型。下面直接比较元素，整数示例使用 MinHeap<int, int>；对于记录类型，其比较运算应按关键码进行。

Insert 和 Remove 的返回值表示操作是否成功；删除得到的最小元素通过参数 x 返回。

2. 堆的定义

先考虑怎样让最小元素始终处在树根。我们可以要求每个父结点都不大于它的孩子；沿路径逐层比较，就能把根与任意后代联系起来。

但只有大小关系还不够：若树退化成一条长链，调整元素仍可能经过所有结点。因此，还要限制树的形状。

2.1 完全二叉树

完全二叉树中，除最后一层外，每一层都排满；最后一层的结点从左到右连续排列，中间没有空缺。

例如：

            9
          /   \
        17     65
       /  \   /  \
      23  45 78  87
     /
    53

这棵树最后一层只有一个结点，而且位于最左边，因此是完全二叉树。若保留最后一层右边的位置，却空出它左边应有的位置，就不再满足完全二叉树的要求。

这个形状使树的高度较小，也使结点可以紧凑地存放在数组中。

2.2 最小堆与最大堆

一棵完全二叉树，如果每个父结点的关键码都小于或等于它的每个孩子，就称为最小堆。上图就是最小堆，例如：

  • 9 ≤ 17，9 ≤ 65；
  • 17 ≤ 23，17 ≤ 45；
  • 65 ≤ 78，65 ≤ 87；
  • 23 ≤ 53。

沿着根到任意结点的路径，每一步都满足“父结点 ≤ 子结点”。通过大小关系的传递性，根结点就小于或等于树中所有元素。因此，最小堆的根结点存放最小值，这个位置称为堆顶。

最大堆把关系反过来，要求每个父结点的关键码都大于或等于它的每个孩子。于是，最大值位于堆顶。

这里允许等号。数组中即使包含重复值，也可以建成堆。

最小堆和最大堆都把元素组织成完全二叉树，每个结点最多有两个孩子，因此这一结构也称为二叉堆。“二叉”说明结构，“最小”或“最大”说明父子间的排列规则。

优先级相同的元素可以同时存在，但堆不保证它们按进入顺序取出；若需要保留先后次序，可以把进入顺序也纳入比较条件。

2.3 堆中哪些元素有大小关系

堆只约束父子关系，并由此约束祖先与后代。左右兄弟之间、互不包含的子树之间，没有额外的大小要求。

这意味着，按层次读出堆的元素，通常不会得到一个有序序列；二叉搜索树的“左子树较小、右子树较大”规则也不适用于堆。

再看两个分别满足最小堆、最大堆条件的例子：

最小堆                         最大堆

           9                             87
         /   \                         /    \
       17     65                      78      53
      /  \   /  \                    /  \    /  \
     23  45 78  87                  45  65   9   31
    / \                            / \
   53 31                          17 23

从上到下、每层从左到右读出结点，得到：

最小堆：[9, 17, 65, 23, 45, 78, 87, 53, 31]
最大堆：[87, 78, 53, 45, 65, 9, 31, 17, 23]

检查它们时，只需检查每个存在的父子对。以最小堆中的 23 为例，它的两个孩子是 53 和 31，两者都不小于 23，已经满足要求；不要求左孩子 53 小于右孩子 31。

3. 用数组存储堆

3.1 按层次编号

将完全二叉树从上到下、每层从左到右编号，根结点编号为 0，然后把编号当作数组下标。

前面的八结点最小堆存储为：

下标： 0   1   2   3   4   5   6   7
元素： 9  17  65  23  45  78  87  53

因为完全二叉树的结点连续排列，数组里不需要为缺失的中间结点预留位置，也不需要额外存储左右孩子指针。

设当前元素个数为 n，有效下标是 0,1,…,n−1。对于下标为 i 的结点：

关系 下标 存在条件
父结点 ⌊(i−1)/2⌋ i>0
左孩子 2i+1 2i+1<n
右孩子 2i+2 2i+2<n

符号 ⌊x⌋ 表示向下取整。例如，下标 3 的父结点是 ⌊(3−1)/2⌋ = 1，左孩子是 7，右孩子应在 8。当 n=8 时，左孩子存在，右孩子不存在。

根结点没有父结点。计算父结点下标之前，应先检查 i > 0。

用 Ki 表示下标 i 处的关键码，最小堆的条件可以写成：

Ki≤K2i+1（左孩子存在时）,Ki≤K2i+2（右孩子存在时）.

最大堆将这两个不等号都改为 ≥。这些公式只用于实际存在的孩子。

3.2 最后一个非叶子结点

叶子结点没有孩子。完全二叉树中的非叶子结点至少有左孩子，所以其下标满足：

2i+1<n.

由于下标是整数，可以写成：

2i+1≤n−1,2i≤n−2,i≤⌊n−22⌋.

因此，当 n≥2 时，最后一个非叶子结点的下标是：

⌊n−22⌋=⌊n2⌋−1.

例如，n=8 时，下标 0、1、2、3 是非叶子结点，4、5、6、7 是叶子结点。建堆时会用到这个分界。

3.3 元素个数与容量

采用固定容量数组实现堆时，需要区分三个数据成员：

数据成员 含义
heap 存放元素的数组
currentSize 当前有效元素个数
maxHeapSize 数组能够容纳的元素个数

例如，数组容量为 20，当前只存了 8 个元素，则有效堆只包括 heap[0..7]。后面的存储位置不属于当前堆。

因此：

  • currentSize == 0 表示堆空；
  • currentSize == maxHeapSize 表示堆满；
  • 将 currentSize 设为 0，就能逻辑清空堆。

逻辑清空后，原数组空间仍可复用，旧值即使还留在内存中，也不再作为堆内元素参与运算。

3.4 最小堆的类定义

用固定容量数组实现最小堆，各操作组织如下：

#include <cstdlib>
#include <iostream>
#include <new>
#include <stdexcept>

constexpr int DefaultSize = 20;

template <class T, class E>
class MinHeap : public MinPQ<T, E> {
public:
    explicit MinHeap(int sz = DefaultSize);
    MinHeap(const E arr[], int n);

    ~MinHeap() override {
        delete[] heap;
    }

    bool Insert(const E& x) override;
    bool Remove(E& x) override;

    bool IsEmpty() const {
        return currentSize == 0;
    }

    bool IsFull() const {
        return currentSize == maxHeapSize;
    }

    void MakeEmpty() {
        currentSize = 0;
    }

    MinHeap(const MinHeap&) = delete;
    MinHeap& operator=(const MinHeap&) = delete;

private:
    E* heap;
    int currentSize;
    int maxHeapSize;

    void siftDown(int start, int m);
    void siftUp(int start);
};

两个构造函数分别用于建立空堆和从已有数组建堆。siftDown、siftUp 分别完成向下、向上调整，是后续操作的核心。

4. 建立堆：从局部子树开始

建立堆有两种常见情形。

一种是建立空堆：分配空间，将 currentSize 设为 0。随后每来一个元素，就执行一次插入。

另一种是已经有一个包含 n 个元素的数组，需要一次性将它调整为堆。这时可以使用筛选法建堆，也称自底向上建堆。

先考虑把下面的数组调整成最小堆：

[53, 17, 78, 23, 45, 65, 87, 9]

如果用另一块数组存放堆，需要先为它安排至少 n 个位置，复制所有元素，并令 currentSize = n。也可以直接在原数组上调整。

4.1 建立空堆

空堆构造函数先确定容量、分配空间，再把当前元素个数设为 0：

template <class T, class E>
MinHeap<T, E>::MinHeap(int sz) {
    if (sz < 0) {
        throw std::invalid_argument("容量不能为负数");
    }

    maxHeapSize = (DefaultSize < sz) ? sz : DefaultSize;
    heap = new (std::nothrow) E[maxHeapSize];
    if (heap == nullptr) {
        std::cerr << "堆存储分配失败！\n";
        std::exit(EXIT_FAILURE);
    }
    currentSize = 0;
}

容量取 sz 和 DefaultSize 中较大的一个。例如，传入 8 时分配 20 个位置，传入 50 时分配 50 个位置；无论容量多大，新建空堆的有效元素个数都是 0。

4.2 为什么从最后一个非叶子结点开始

单个叶子结点自身就是一个最小堆，因为它没有需要比较的孩子。

假设某个结点的左右子树已经分别是最小堆，那么剩下的问题就集中在这个结点：它的值可能大于孩子。只要把这个值放到合适的位置，以它为根的整棵子树就能成为最小堆。

因此，可以先处理最下层的非叶子结点，再逐步向上处理。用数组下标表示，就是：

floor(n/2) - 1, floor(n/2) - 2, ..., 1, 0

每处理一个结点，都进行一次向下调整，也称下滑、下沉或 siftDown。

这里有两个不同的方向：

  • 选择待处理结点的顺序，从下层到上层；
  • 处理某一个结点时，其元素沿孩子方向向下移动。

4.3 向下调整怎样进行

向下调整需要知道待调整结点下标 start，以及当前堆的最后一个有效下标 m。它要求 start 的左右子树已经分别满足堆性质；调整目标是让以 start 为根的子树也满足堆性质。

以最小堆为例，每一轮这样做：

  1. 找出当前结点较小的孩子；若只有左孩子，就选左孩子。
  2. 如果当前待放置的值不大于这个孩子，就可以停下。
  3. 否则，让较小的孩子上移，继续到这个孩子原来的位置处理。
  4. 到达叶子，或者找到可以停下的位置后，放入原先待调整的值。

为什么要选较小的孩子？

假设待调整值是 53，两个孩子分别是 9 和 65。若把 65 提上来，新的父结点 65 仍大于另一个孩子 9，这一层依然不满足要求。选择 9 上移，才能同时照顾两个孩子的大小关系。

为了减少赋值次数，可以先把原值保存到变量 temp 中，将它原来的位置看成一个待填位置。沿途只把孩子复制上来，最后再把 temp 写回。这个“待填位置”是理解算法的方式，数组并不真的增加一个空元素。

下面用 siftDown 实现这个过程。m 是最后一个有效下标，包含这个位置：

template <class T, class E>
void MinHeap<T, E>::siftDown(int start, int m) {
    if (start < 0 || start > m) return;

    int i = start;
    int j = 2 * i + 1;
    E temp = heap[i];

    while (j <= m) {
        if (j < m && heap[j] > heap[j + 1]) {
            ++j;
        }
        if (temp <= heap[j]) break;

        heap[i] = heap[j];
        i = j;
        j = 2 * i + 1;
    }
    heap[i] = temp;
}

开始时，j 指向左孩子。只有 j < m 时，右孩子 j+1 才存在，才能访问并比较它。两个孩子相等时，这段代码选左孩子，选右孩子也能得到合法的堆。

temp 在整个过程中保存同一个值。数组里可能暂时出现重复值，因为某个孩子已复制到父位置、原位置尚未覆盖；最后一次写回后，数组中元素的数量和组成都会保持不变。

4.4 例题：把给定数组调整为最小堆

题目： 将数组 [53, 17, 78, 23, 45, 65, 87, 9] 用筛选法调整为最小堆。

解答： 初始树形为：

            53
          /    \
        17      78
       /  \    /  \
      23  45  65  87
     /
    9

元素个数为 8，最后一个非叶子结点下标为 ⌊8/2⌋−1 = 3，所以依次调整下标 3、2、1、0。

处理下标 3

待调整值为 23，只有一个孩子 9。将 9 上移，23 放到下标 7：

[53, 17, 78, 9, 45, 65, 87, 23]

现在，以原下标 3 为根的子树已经是最小堆。

处理下标 2

待调整值为 78，两个孩子是 65 和 87。选较小的 65 上移，将 78 放到下标 5：

[53, 17, 65, 9, 45, 78, 87, 23]

处理下标 1

待调整值为 17，两个孩子是 9 和 45，选 9 上移。来到下标 3 后，剩下的孩子为 23。由于 17 ≤ 23，将 17 放在下标 3，停止：

[53, 9, 65, 17, 45, 78, 87, 23]

处理下标 0

待调整值为 53，其下沉路径如下：

待填位置 孩子的值 操作
下标 0 9、65 9 < 53，把下标 1 的 9 提到下标 0
下标 1 17、45 17 < 53，把下标 3 的 17 提到下标 1
下标 3 只有 23 23 < 53，把下标 7 的 23 提到下标 3
下标 7 无孩子 放入 53

最后得到：

[9, 17, 65, 23, 45, 78, 87, 53]

            9
          /   \
        17     65
       /  \   /  \
      23  45 78  87
     /
    53

每一轮结束后的数组汇总如下：

阶段 数组
初始 [53, 17, 78, 23, 45, 65, 87, 9]
调整下标 3 后 [53, 17, 78, 9, 45, 65, 87, 23]
调整下标 2 后 [53, 17, 65, 9, 45, 78, 87, 23]
调整下标 1 后 [53, 9, 65, 17, 45, 78, 87, 23]
调整下标 0 后 [9, 17, 65, 23, 45, 78, 87, 53]

4.5 从数组建立堆

数组构造函数接收 n 个元素，先复制，再从最后一个非叶子结点向根依次筛选：

template <class T, class E>
MinHeap<T, E>::MinHeap(const E arr[], int n) {
    if (n < 0 || (n > 0 && arr == nullptr)) {
        throw std::invalid_argument("数组或元素个数无效");
    }

    maxHeapSize = (DefaultSize < n) ? n : DefaultSize;
    heap = new (std::nothrow) E[maxHeapSize];
    if (heap == nullptr) {
        std::cerr << "堆存储分配失败！\n";
        std::exit(EXIT_FAILURE);
    }

    for (int i = 0; i < n; ++i) {
        heap[i] = arr[i];
    }
    currentSize = n;

    int currentPos = currentSize / 2 - 1;
    while (currentPos >= 0) {
        siftDown(currentPos, currentSize - 1);
        --currentPos;
    }
}

数组非空时，arr 应包含至少 n 个有效元素。容量取默认容量与 n 中较大的值，确保能够容纳全部元素。

对于 n ≥ 2，最后一个非叶子结点也可以写成 (n-2)/2。代码采用 n/2-1，它在 n=0 或 n=1 时都得到 -1，循环自然跳过。直接将 (n-2)/2 用到 n=1 时，C++ 的整数除法会得到 0，不能照搬数学上的向下取整结果。

每次传给 siftDown 的右端点都是 currentSize-1，但函数沿孩子下标只访问当前结点的子树。

4.6 建堆的正确性

先说明一次 siftDown 为什么能成功。

它开始时，左右子树已经是堆。选出的较小孩子不大于另一个孩子，也不大于它自己子树中的任何后代，所以把它提到待填位置，能维护这一位置与下方元素的关系。

接下来可能不合适的地方，只剩 temp 应放在哪里；算法沿选中的子树继续处理。找到 temp 不大于孩子的位置，或到达叶子后写回，整个子树的关系便恢复了。

再看整个建堆过程。

开始时所有叶子都已是堆。处理下标 currentPos 时，它的孩子下标都比它大；这些孩子要么是叶子，要么已经处理过。因此，每次调用向下调整都满足前提。

处理完根结点 0 后，以根为起点的整棵树就是最小堆。

5. 插入元素与向上调整

设原数组已经表示一个最小堆，要插入新元素 x。插入后既要保持完全二叉树的形状，也要恢复父子大小关系。

5.1 为什么插在数组末尾

完全二叉树最后一层从左到右连续排列，所以新增结点只能占据下一个层次编号位置，即原数组的下标 n。

将 x 放到末尾后，原有父子关系都没有改变。新增结点没有孩子，唯一可能出现的问题是：x 小于它的父结点。

因此，从新增位置向上比较即可：如果父结点较大，就把父结点下移；继续检查更上一层。遇到一个不大于 x 的父结点，或已经到达根结点，就停下。

这称为向上调整，也称上浮或 siftUp。

5.2 例题：插入 11

题目： 向最小堆 [9, 17, 65, 23, 45, 78, 87, 53] 插入 11。

解答： 先把 11 放到下标 8：

[9, 17, 65, 23, 45, 78, 87, 53, 11]

它的父结点下标为 ⌊(8−1)/2⌋ = 3，父结点值是 23。由于 11 < 23，11 应向上移动。接着依次比较 17、9。

为方便观察，下面按逐次交换的形式写出逻辑状态；后面的实现用暂存值和移动父结点完成同样的调整。

追加 11：       [9, 17, 65, 23, 45, 78, 87, 53, 11]
越过父结点 23：[9, 17, 65, 11, 45, 78, 87, 53, 23]
越过父结点 17：[9, 11, 65, 17, 45, 78, 87, 53, 23]

此时父结点是根结点 9，满足 9 ≤ 11，停止。最终树形为：

            9
          /   \
        11     65
       /  \   /  \
      17  45 78  87
     / \
    53 23

11 的路径是 8 → 3 → 1，没有到达根。一次插入并不总要走完整棵树的高度。

5.3 向上调整的实现

template <class T, class E>
void MinHeap<T, E>::siftUp(int start) {
    int j = start;
    E temp = heap[j];

    while (j > 0) {
        int i = (j - 1) / 2;
        if (heap[i] <= temp) break;

        heap[j] = heap[i];
        j = i;
    }
    heap[j] = temp;
}

j 是当前待填位置，i 是它的父结点。如果父结点较大，就将其复制到 j，然后让待填位置上移。

与向下调整一样，temp 保存原值，最后只写回一次。

固定容量堆在插入前要检查是否已满：

template <class T, class E>
bool MinHeap<T, E>::Insert(const E& x) {
    if (currentSize == maxHeapSize) {
        std::cerr << "Heap Full\n";
        return false;
    }

    heap[currentSize] = x;
    siftUp(currentSize);
    ++currentSize;
    return true;
}

currentSize 同时也是下一个空闲位置的下标。siftUp 使用显式传入的起点，不依赖成员 currentSize，所以在调整结束后再将元素个数加一。堆满时函数返回 false，不会写入数组。

为什么父结点下移不会破坏其他关系？

原堆中，父结点不大于路径下方的原有元素，也不大于自己的另一个孩子。把它移到下一层后，它仍能压在那些更大的元素上面。

每次移动只把待放置 temp 的位置向上推进一层；当上方父结点不大于 temp 时，上下两侧的关系就都能满足。

6. 删除堆顶与向下调整

这里的删除操作指删除并返回堆顶。在最小堆中，这等价于取出当前最小元素。

6.1 为什么用末尾元素补堆顶

根结点被删除后，需要把剩余元素重新安排为包含 n−1 个结点的完全二叉树。按层次编号，必须消失的位置是原来的最后一个位置。

因此，删除可以分成四步：

  1. 保存堆顶值，作为返回结果。
  2. 将最后一个元素复制到堆顶。
  3. 将有效元素个数减一，排除原来的最后一个位置。
  4. 从堆顶向下调整。

末尾元素原先是叶子。去掉这个叶子后，左右子树中剩余的父子关系仍然成立；替换到根位置的值可能过大，正好满足向下调整的适用情形。

6.2 例题：删除 9

题目： 从插入 11 后的最小堆 [9, 11, 65, 17, 45, 78, 87, 53, 23] 删除堆顶。

解答： 先保存 9，用末尾的 23 补到根位置，再将有效元素个数从 9 改为 8：

[23, 11, 65, 17, 45, 78, 87, 53]

接下来对 23 向下调整：

  • 根的孩子为 11、65，选 11 上移，待放置的 23 来到下标 1。
  • 下标 1 的孩子为 17、45，选 17 上移，23 来到下标 3。
  • 下标 3 只剩左孩子 53。由于 23 ≤ 53，在这里放下 23。

按逐次交换的逻辑状态写为：

末尾补到根：  [23, 11, 65, 17, 45, 78, 87, 53]
越过孩子 11：[11, 23, 65, 17, 45, 78, 87, 53]
越过孩子 17：[11, 17, 65, 23, 45, 78, 87, 53]

本次操作返回 9。操作结束后，新堆顶是 11，它也是剩余元素中的最小值。

6.3 删除的实现与边界

template <class T, class E>
bool MinHeap<T, E>::Remove(E& x) {
    if (currentSize == 0) {
        std::cerr << "Heap empty\n";
        return false;
    }

    x = heap[0];
    heap[0] = heap[currentSize - 1];
    --currentSize;

    if (currentSize > 0) {
        siftDown(0, currentSize - 1);
    }
    return true;
}

x = heap[0] 先保存返回元素，再用末尾值覆盖根。减一后的 currentSize-1 是新的最后一个有效下标，原末尾位置不再参加调整。

若原来只有一个元素，删除后直接得到空堆，不需要向下调整。若原来就是空堆，函数返回 false，不读取 heap[0]，也不改变参数 x。

7. 两种建堆方法与复杂度

设 n 为堆中元素个数。以下假设一次关键码比较、一次数组访问和一次元素赋值都花费常数时间；固定容量数组已经分配好，不把临时扩容计入单次调整。

7.1 单次上浮或下沉

把根结点的深度记为 0，一棵含 n≥1 个结点的完全二叉树，其最大深度为：

h=⌊log2⁡n⌋.

原因是深度为 h 的层从层次编号 2h−1 开始。最后一个结点下标为 n−1，所以它所处的层满足：

2h≤n<2h+1,

从而得到上式。

上浮每轮向父结点走一层，下沉每轮向某个孩子走一层。每轮只做常数次比较和赋值，因此两种调整最坏都需要 O(log⁡n) 时间。

如果第一次比较就能停下，只需要 O(1) 时间。插入和删除堆顶的最坏时间为 O(log⁡n)，并不表示每一次实际操作都必须花这么多时间。

上面的实现使用循环，只需保存少数下标和一个临时元素，因此调整本身的额外空间为 O(1)。

7.2 插入法建堆

从空堆开始，按原数组的顺序执行 Insert，也能建立堆。

仍然插入 53、17、78、23、45、65、87、9，各步结果为：

新插入的元素 插入后数组
53 [53]
17 [17, 53]
78 [17, 53, 78]
23 [17, 23, 78, 53]
45 [17, 23, 78, 53, 45]
65 [17, 23, 65, 53, 45, 78]
87 [17, 23, 65, 53, 45, 78, 87]
9 [9, 17, 65, 23, 45, 78, 87, 53]

本例两种方法恰好得到相同数组。一般情况下，同一组元素可能构成多个合法的堆，两种方法的结果不必一致。

第 k 次插入最坏需要 O(1+log⁡k) 时间，所以总时间上界为：

∑k=1nO(1+log⁡k)=O(nlog⁡n).

这里可以直接理解为：共有 n 次插入，每次最多花 O(log⁡n) 时间。

这个最坏量级能够达到。例如，按严格递减顺序向最小堆插入元素，新元素每次都是当前最小值，需要一路上浮到根。后半段约 n/2 次插入，每次经过的层数都与 log⁡n 同阶。

因此，插入法建堆的最坏时间是 Θ(nlog⁡n)。这里的 Θ 表示上下界属于同一量级。

若输入已经递增，新元素每次都不小于父结点，一次比较即可停止，总时间可以是 Θ(n)。两者描述的是不同输入情况下的表现。

7.3 筛选法建堆为什么是线性时间

筛选法要调整大约 n/2 个非叶子结点，而一次下沉最坏是 O(log⁡n)。直接相乘能得到一个上界，但没有反映不同结点的高度差别。

靠近叶子的结点很多，却只能下沉一两层；能够下沉很多层的结点很少。可以按“最多能下沉多少层”来计算总工作量。

设结点的高度为从该结点到其最深后代的边数，叶子高度为 0。

对于下标 i，向左走一层到 2i+1，向左走两层到：

2(2i+1)+1=4i+3.

继续展开，向左走 k 层到达的下标为：

2ki+(2k−1)=2k(i+1)−1.

在完全二叉树中，同一深度的后代从左侧开始填充。因此，某结点高度至少为 k，当且仅当这个最左侧的第 k 层后代存在，也就是：

2k(i+1)−1<n.

由于两边涉及整数，这等价于：

2k(i+1)≤n,

于是：

i+1≤⌊n2k⌋.

所以，高度至少为 k 的结点恰有 ⌊n/2k⌋ 个。

现在把每个结点的最大下沉层数分层累计：

  • 每个高度至少为 1 的结点贡献第一层；
  • 每个高度至少为 2 的结点再贡献第二层；
  • 每个高度至少为 3 的结点再贡献第三层；
  • 依此类推。

所有结点可下沉层数的总和为：

∑k≥1⌊n2k⌋≤n2+n4+n8+⋯=n.

右侧是等比级数，第一项为 n/2、公比为 1/2，总和为：

n/21−1/2=n.

每下降一层只做常数次操作，再加上各次调用本身的常数开销，总时间为 O(n)。标准筛选法还要遍历全部非叶子结点，这部分就需要线性时间，因此总时间为 Θ(n)。

若先把原数组复制到新数组，复制同样需要 Θ(n) 时间，总量级仍为 Θ(n)。

原地调整的额外空间为 O(1)；另建存储数组则需要 O(n) 的元素存储空间。

7.4 操作对照

操作 时间复杂度 条件或说明
查看堆顶 O(1) 非空堆，直接访问下标 0
插入一个元素 最坏 O(log⁡n) 数组容量足够，上浮
删除堆顶 最坏 O(log⁡n) 非空堆，下沉
筛选法建堆 Θ(n) 逐个处理非叶子结点
插入法建堆 最坏 Θ(nlog⁡n) 从空堆逐个插入
判空、判满 O(1) 检查元素个数
逻辑清空 O(1) 只把有效元素个数设为 0
查找任意给定值 最坏 O(n) 没有额外索引时，可能检查所有元素

如果底层使用会自动扩容的动态数组，某次插入可能因复制旧元素而额外花费 O(n) 时间；通常分析的 O(log⁡n) 指调整部分，或结合扩容策略后的均摊界。

资源释放、复杂记录的复制成本，也应在实际问题中另行计入。

8. 使用堆时容易混淆的地方

一个数组只做一次根结点下沉，不一定就能变成堆。

下沉要求左右子树已各自成堆。任意数组需要先处理下面的结点，才适合处理根。

插入与删除不能忽略完全二叉树的形状。

插入占据新的末尾位置；删除堆顶时，先用末尾元素补根，并缩短有效区间。调整过程中只移动元素的值，结点位置始终保持连续。

最小堆的数组顺序不等于升序。

例如 [9, 17, 65, 23, 45, 78, 87, 53] 是最小堆，其中 65 却排在 23 前面。每次删除最小值并重新调整，才能逐个得到升序输出。

查找某个任意元素没有堆顶这样的便利。

堆的顺序信息不足以像二叉搜索树那样，根据一次比较就选择一边继续查找。若题目要求删除任意元素，需要先知道它的位置；找到后还要根据替换值与父子结点的关系，选择上浮或下沉。

最大堆也使用同样的结构。

下沉时选较大的孩子，待放置值不小于孩子时停止；上浮时父结点不小于待插入值就停止。它们同样只沿一条路径调整，复杂度不变。

堆常用于反复取出最小值或最大值的场景。例如，Huffman 树的构造要反复取出两个最小权值、合并后再插回，这正好对应最小优先级队列的操作。

堆排序也利用堆顶的极值性质；若要在原数组中排成升序，常见方法是建立最大堆，每次把最大值交换到当前有效区间末尾，再缩短堆的范围并调整。

9. 练习

练习一：判断最小堆

题目： 以下数组按层次表示完全二叉树，哪些是最小堆？若不满足，请指出违反要求的父子对。

A = [3, 5, 4, 9, 8, 6]
B = [3, 5, 4, 9, 2, 6]
C = [3, 3, 4, 9, 8, 6]

解答：

A 是最小堆：

  • 3 ≤ 5、4；
  • 5 ≤ 9、8；
  • 4 ≤ 6。

B 中下标 1 的 5 大于其右孩子、下标 4 的 2，违反最小堆条件。

C 也成立，父子相等是允许的。

练习二：连续插入与删除

题目： 从最小堆 [2, 5, 4, 9, 7, 8] 出发，先插入 3，再删除堆顶，写出两个操作结束后的数组与删除返回值。

解答： 3 追加在下标 6，父结点下标为 2，值为 4。3 < 4，向上移动一层；随后与根 2 比较，2 ≤ 3，停止：

插入后：[2, 5, 3, 9, 7, 8, 4]

删除时先保存 2，用末尾 4 补根，缩短数组：

[4, 5, 3, 9, 7, 8]

在孩子 5、3 中选 3 上移，待调整的 4 到下标 2。它只有一个孩子 8，满足 4 ≤ 8，停止：

删除后：[3, 5, 4, 9, 7, 8]
返回值：2

练习三：解释建堆顺序

题目： 为什么筛选法可以从最后一个非叶子结点一直处理到根，却不能对任意数组只从根开始下沉一次就结束？

解答： 从下往上处理时，每个结点的孩子子树都已经是堆，符合向下调整的前提。

若直接处理任意数组的根，下方可能仍有违反大小关系的父子对；一次下沉只访问一条路径，其他路径的问题会保留下来。

例如 [1, 9, 2, 3] 中，根 1 已经小于两个孩子，根结点下沉会立刻停止；但 9 > 3，整棵树仍然不满足最小堆条件。
